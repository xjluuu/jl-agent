# Launch Plan

## Positioning

JL-Agent should not be positioned as "another agent framework."

Use this angle:

> A one-file local AI agent for restricted enterprise environments, with optional Windows EXE deployment.

Sharper version for finance/enterprise audiences:

> A local enterprise AI agent with role-based permissions, auditable tools, parallel research, and Risk Agent veto workflows for restricted networks.

## Core audience

- Developers inside restricted company networks
- IT admins who need local AI tools
- Analysts and operations users on restricted company computers
- Teams that need Python mode on macOS/Linux and EXE mode on Windows
- Teams with internal model gateways
- Finance, research, compliance, and operations teams that analyze many local documents
- People who dislike Docker-heavy agent stacks

## Launch sequence

### Day 0

- Post "Show HN: JL-Agent..." on Hacker News

### Day 3-7

- Fix quick docs issues
- Add one small feature requested by early users
- Cut `v0.1.1`

## Hooks

- One Python file
- Cross-platform Python mode
- Windows EXE for coworkers without Python
- Works in restricted company environments
- Role-based admin / maintainer / viewer permissions
- Parallel research for market, policy, company, and document analysis
- Risk Agent one-vote veto for stock, project, and compliance research
- Financial research workflows without becoming a trading bot
- Local audit log
- Dangerous command blocking
- No Docker required

## Success metrics

- 10 stars: public page is understandable
- 100 stars: positioning works
- 500 stars: demo and distribution work
- 1,000 stars: start building plugin/code-index and research workflow roadmap

## Monetization path

Do not block the open-source core. Offer paid:

- Enterprise setup
- Internal model gateway integration
- Windows packaging support
- Configurable storage paths for different organizations
- Knowledge-base migration
- Workflow customization
- Finance/market research templates with Risk Agent veto rules
